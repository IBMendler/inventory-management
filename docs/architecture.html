Factory Inventory Management System

Architecture overview: a Vue 3 single-page app talking to a FastAPI service backed by in-memory JSON data.

System architecture

Three tiers, all running locally. There is no database; data is loaded from JSON files at server start.

Frontend

Vue 3 + Vite · localhost:3000
  • Views: Dashboard, Inventory, Orders, Demand, Spending, Reports
  • Shared filter state (useFilters)
  • Centralised API client (api.js, axios)
  • English / Japanese (useI18n)
  • Custom SVG charts, detail modals

Data flow

How a filter change on screen becomes updated numbers and charts.

  1. User changes a filterTime period, warehouse, category or order status in the filter bar.
  2. Shared state updatesuseFilters holds the selections as module-level refs, so every view sees the same values.
  3. View calls the API clientgetCurrentFilters() builds the filter object; api.js turns it into query params and skips any set to "all".
  4. FastAPI filters in memoryThe endpoint applies apply_filters / filter_by_month to the loaded lists.
  5. Pydantic validates the responseTyped models serialise the result to JSON.
  6. Vue re-rendersRaw data lands in refs; totals and chart series are computed properties.

Things worth knowing

  • The API base URL is hardcoded to http://localhost:8001/api in api.js; the Vite dev server does not proxy.
  • State is not persisted. Restarting the backend reloads the JSON files.
  • Backlog.vue exists but has no route of its own in main.js.
  • The backend defines a CreatePurchaseOrderRequest model, but no endpoint using it exists yet.
